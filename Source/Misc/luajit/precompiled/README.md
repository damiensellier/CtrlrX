# Precompiled LuaJIT

Prebuilt LuaJIT for people who build CtrlrX through the **Projucer** exporters
(Visual Studio, Xcode) rather than CMake. The `.jucer` files point their
`libraryPath` and `headerPath` here and extract the bundle themselves in a
pre-build step, so a fresh clone builds with no extra action and no local CMake.

The CMake build ignores this directory entirely — it builds LuaJIT from source
via `cmake/luajit/`. See [`Doc/LUAJIT.md`](../../../../Doc/LUAJIT.md).

## What is tracked

| Path | Tracked? |
|---|---|
| `luajit-windows.zip`, `luajit-macos.zip` | yes |
| `manifest-windows.json`, `manifest-macos.json` | yes |
| `windows/`, `macos/` (extracted) | **no** — recreated by every build |

Never commit the extracted directories, and never copy anything out of them into
`Source/Misc/luajit/src/`. That tree stays byte-identical to upstream, and the
CMake build fails at configure time if it finds anything there.

There is no Linux bundle: `LINUX_MAKE` and `CODEBLOCKS_LINUX` are not IDEs, and
every Linux developer already has CMake. Build LuaJIT with
`cmake -S cmake/luajit -B build-lj && cmake --build build-lj`, then add
`build-lj/gen/common` to `headerPath` and `build-lj` to `libraryPath`.

## Bundle contents

```
windows/include/luajit.h                  generated by the build, not in upstream src/
windows/lib/x64/Release/lua51.lib         built /MD
windows/lib/x64/Debug/lua51.lib           built /MDd
windows/manifest.json

macos/include/luajit.h
macos/lib/libluajit.a                     universal arm64 + x86_64, deployment target 10.13
macos/manifest.json
```

Windows ships two libraries because the Projucer sets no `winRuntimeLibrary` and
therefore uses the **dynamic** CRT, where `/MD` and `/MDd` are not
interchangeable. (The CMake build uses the *static* CRT — `cmake/JUCEDefaults.cmake`
forces it — which is why these are built by a job of their own rather than lifted
out of the plugin build.) x64 only: 32-bit is not shipped, and a `Win32` config
fails loudly with `LNK1112` rather than linking something wrong.

## Staleness

`manifest-<os>.json` records the git object ids of the inputs each bundle was
built from:

| key | path |
|---|---|
| `luajit_src` | `Source/Misc/luajit/src` |
| `luajit_dynasm` | `Source/Misc/luajit/dynasm` |
| `luajit_relver` | `Source/Misc/luajit/.relver` |
| `cmake_luajit` | `cmake/luajit` |

`cmake/luajit/check_precompiled_drift.py` compares those against the tree on every
push. It fingerprints *inputs*, not the built artefacts: `lib.exe` stamps a
timestamp into the archive and every `.obj`, zip stores mtimes, and the runner
images bump MSVC and Xcode monthly — so comparing output bytes would go red on
identical source, on a schedule, and get ignored.

Note this deliberately does not track the compiler version. A library built from
identical source by an older toolchain is still the library that was validated.

## Regenerating

1. Actions → **LuaJIT** → *Run workflow* (it also runs automatically whenever the
   check finds the bundles stale).
2. Download the `luajit-precompiled-windows` and `luajit-precompiled-macos`
   artifacts.
3. Copy the `.zip` and `.json` out of each into this directory. Do **not** unzip
   the inner zip here.
4. Commit both files.
